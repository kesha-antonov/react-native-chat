# AGENTS.md

Guidance for AI coding agents working **inside this repository**.

If you are instead helping someone *use* this library in their own app, read
[`llms.txt`](llms.txt) - it is a compact integration guide and does not require the checkout.

## What this is

`@kesha-antonov/react-native-chat` is a chat UI component library for React Native and
Web - a maintained continuation of `react-native-gifted-chat`. It ships as compiled
JavaScript plus type definitions; there is no native code in this package.

## Setup

Requires **Node >= 20** and **Yarn 4** (pinned via `packageManager`; use `yarn`, never `npm`).

```bash
yarn install          # library
cd example && yarn install && cd ..   # example app - a SEPARATE yarn project
```

The repo is **not** a Yarn workspace. `example/` has its own `package.json`, its own
`yarn.lock`, and its own `node_modules`, and depends on the library via `link:..`. Installing
at the root does not install the example, and vice versa.

## Commands

Run these from the repo root:

| Command | What it does |
| --- | --- |
| `yarn test` | Jest suite, run under `TZ=Europe/Paris` (snapshots contain formatted times, so the timezone is pinned). Must stay green. |
| `yarn test:watch` / `yarn test:coverage` | Same suite, watching or with coverage. |
| `yarn typecheck` | `tsc --noEmit` over `src/`. Must stay clean. |
| `yarn lint` | ESLint over **both** `src/` and `example/`. Must report 0 errors and 0 warnings. |
| `yarn lint:fix` | Auto-fix what ESLint can. |
| `yarn build` | `rm -rf lib`, `tsc` for the declarations, then Babel with the React Compiler (`babel.build.cjs`) for the JavaScript - emits `lib/`, which is gitignored and is what gets published. The build fails if the compiler has to skip any component. |
| `yarn prepublishOnly` | lint + test + build, i.e. the full gate. |

Inside `example/`: `yarn lint` and `yarn typecheck` cover the example app on its own. Note
that the root `yarn lint` also lints `example/`, under **stricter** rules than the example's
own `expo lint` - so a change that passes `cd example && yarn lint` can still fail at the root.
Always run the root `yarn lint` before you finish.

A husky `pre-commit` hook runs `lint-staged`. Its glob is `src/*.{json,js,jsx,ts,tsx}`, which
matches only the **top level** of `src/` - a change under `src/MessagesContainer/` or
`src/components/` is committed without `lint:fix` touching it. Do not rely on the hook; run
the root `yarn lint` yourself.

## Layout

A component past ~300 lines is a folder of parts: an `index.tsx` that keeps the old import path
and public exports, plus single-purpose hooks, components, `styles.ts`, `constants.ts`, `types.ts`.
Keep new work in that shape.

```
src/                     library source - the only thing published (as compiled lib/)
  Chat/                  <Chat>: ChatWrapper (providers, Chat.append/toggleReaction), Chat.tsx,
                         ComposerHost, and hooks (useComposerState, useMessageActions, ...)
  ChatList/              <ChatList>, the list of chats, and useChatList
  MessagesContainer/     the message list (Legend List, oldest first), day header, scroll handling;
                         rowStore.ts (rows by id), rowConfig.ts (shared row props, useRowSettings)
  Bubble/                one bubble: useBubbleLayout + BubbleBody / BubbleContent / BubbleMeta /
                         BubbleMenu
  Message/               a message row (avatar, selection, swipe-to-reply)
  InputToolbar/          the composer: field, emoji / attach buttons, record / send slot, take bar
  MessageVideo/          inline video and round notes (RoundNotePlayer + its hooks)
  Day/                   the date separator; the animated floating header lives in
                         MessagesContainer/components/DayAnimated
  Reactions/ Reply/      emoji reactions, swipe-to-reply
  TypingIndicator/       the three-dot bubble
  components/            shared components; the large ones are folders: ContextMenu/, RecordButton/,
                         VoiceMessageInput/, VideoNoteCapture/ (round-note take),
                         VideoNoteRecorder/, WaveformPlayer/, mediaViewer/ (photo gallery)
  gestures/              shared gesture hooks (useRowSwipe: swipe-to-reply, swipe-to-archive)
  store.ts motion.ts     the state-store primitive; shared easings
  emoji/                 the built-in emoji keyboard and grid; emojiData.ts is generated by
                         scripts/build-emoji-data.cjs from emoji-datasource - do not edit it by hand
  attachments/           the built-in attachment menu and the pickers behind it
  optional/              the optional-peer registry: one literal require per peer, each in its own try
  hooks/                 useTheme, useLabels, useStreamingMessages, …
  locales/ i18n.ts       15 built-in UI translations, one file per language; en is the default
  Theme.ts Icons.ts      theme tokens and the overridable icon registry
  rtl.ts                 RTL detection and position mirroring
  linkParser.tsx         URL / phone / email / mention / hashtag matching for MessageText
  logging.ts             branded warning() / error() helpers
  Models.ts              IMessage, User, QuickReplies, MessageReaction - the public data model
  index.ts types.ts      public API surface; anything not exported here is internal
  __tests__/             Jest tests, colocated with the source they cover
tests/setup.ts           global Jest mocks (reanimated, worklets, safe-area, keyboard)
example/                 Expo demo app - separate yarn project, consumes the built lib/
expoSnack/               single-file demo for snack.expo.dev; not linted or built by CI
docs/                    ARCHITECTURE.md (rules the library is built to), MIGRATION.md, STREAMING.md
llms.txt                 integration guide for agents using the library - update it with the API
```

A day separator is rendered by the list itself (`MessagesContainer/components/Item`), guarded
by `isSameDay`, *around* whatever `renderMessage` returns. A custom `renderMessage` must not
render its own `<Day>` - it would print a pill above every message.

## Conventions

Style is enforced by ESLint (`@stylistic`), so run `yarn lint:fix` rather than matching by eye:

- **no semicolons**, single quotes, 2-space indent, single quotes in JSX
- a space before a function's parameter list: `export function useThemeColor (props) {`
- **no braces around a single-statement block**, and the statement goes on the next line
  (`curly: multi` + `nonblock-statement-body-position: below`):
  ```ts
  if (!currentMessage?.createdAt || isSameDay(currentMessage, previousMessage))
    return null
  ```
- trailing commas on multiline arrays/objects/imports, none on function args; arrow params
  are unparenthesised when there is exactly one (`arrow-parens: as-needed`)
- imports are sorted by `perfectionist/sort-imports` - `yarn lint:fix` will reorder them
- comments explain *why*, not *what*; several existing ones cite the issue they fix
- user-visible diagnostics go through `logging.ts` (`warning`, `error`), which prefixes them
  with the package name, rather than a bare `console.*`

**Write for the React Compiler.** `lib/` is compiled with it, so every app gets its memoization,
and the build fails on a component it cannot compile (see [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)
for the rules the library is built to). ESLint runs the compiler's own checks over `src/`. In practice:

- shared values from JS code (effects, handlers, gesture-hook configs) are read with `.get()` and
  written with `.set()`, not `.value`: the compiler turns a `.value` read inside a callback into
  a memo dependency and reads it on every render, and the build fails when it finds one
  (`scripts/check-compiled.cjs`)
- no `ref.current` reads during render, and no "latest value" writes in the render body - write
  the ref in a `useLayoutEffect` (or `useInsertionEffect` when another layout effect reads it)
- no `eslint-disable` of `react-hooks` rules: one suppression makes the compiler skip the whole
  component
- no `??=`, and no `try/finally` inside a component or hook - move the body to a module-level
  helper
- a gesture hook's callbacks (`usePanGesture({ onUpdate })`...) must stay inline in its config:
  compiled, they are hoisted into memo blocks where the worklets plugin no longer finds them, and
  the gesture silently runs nothing on the UI thread. Jest cannot see this (it runs them on JS).
  Put `'use no memo'` in a hook or component whose gesture callbacks write shared values, and
  mark callbacks handed in from elsewhere with `'worklet'` (see `src/gestures/useRowSwipe.ts`)
- per-chat state shared between components goes through `src/store.ts` (`createStore`,
  `createKeyedStore`, `useStore`, `useKeyedValue`), keyed by message id where rows read it;
  easings and the overshoot curve come from `src/motion.ts`
- state that changes often lives in a store read by the one component that shows it, never in
  `Chat`: the composer text, reply and edit (`Chat/useComposerState`, read by `ComposerHost`),
  recording time and level (`components/recordingMeter.ts`). A row reads a setting that concerns
  only some rows through `useRowSettings(selector)`, not the shared row config. Render-count tests
  (`composerRenderChurn`, `rowRenderChurn`) pin this: a keystroke, reply, edit or recording tick
  must not re-render `Chat` or the rows
- taps inside a message that sits under gesture handlers use a gesture-handler tap
  (`useTapGesture`, as `PressableBubbleRow` and the round note do), not `Pressable`: on Android a
  real finger's touch can be taken from React Native's responder before release, and injected
  test taps (adb, argent) do not show it

Jest runs the library through the same compiler (`babel.config.cjs`), so tests see the shipped
behaviour: a compiled component does not re-call an unchanged render prop, so a test cannot use one
as a probe that its parent rendered (use `React.Profiler`), and rows mount a frame after `Chat`
lays out, so a test that looks at them awaits `waitForRows()` first.

**Never pass a dependency array to a Reanimated worklet hook.** `useAnimatedStyle`,
`useDerivedValue`, `useAnimatedProps` and `useAnimatedReaction` all log
`[Reanimated] dependencies should only be used in web implementation.` once per call per
render when given one on native, and a hook inside a list row turns that into thousands of
lines. The array is dead weight anyway: with the Babel plugin the hook derives its inputs
from the worklet's closure on both native and web. `react-hooks/exhaustive-deps` does list
`useAnimatedStyle` / `useAnimatedProps` / `useDerivedValue` (and the scroll and gesture
handlers) in `additionalHooks`, but it only fires when an array is already present, so it
will never ask you to add one.

Public API changes go through `src/index.ts` / `src/types.ts`. Adding a prop means updating
the README's props reference (`## 📖 Props Reference`), and `llms.txt` when it changes how an app
uses the library, in the same change.

## Testing

Jest with `@testing-library/react-native` **v14**, so `render`, `fireEvent`, `act` and
`renderHook` are all **async** - `await` them, and make the test function `async`:

```tsx
it('does a thing', async () => {
  const { getByText } = await render(<Chat messages={[]} onSend={() => {}} user={{ _id: 1 }} />)
  await fireEvent.press(getByText('Send'))
})
```

Other things worth knowing before you write a test:

- v14 renders through `test-renderer`, not the deprecated `react-test-renderer`. Only **host**
  elements exist in the tree, so `UNSAFE_getByType`/`UNSAFE_getByProps` are gone - query by
  role, text or testID, or read `toJSON()`.
- v14 enforces React Native's "text strings must be rendered within a `<Text>`" invariant.
  A fixture that returns a bare string will throw.
- `tests/setup.ts` mocks reanimated, worklets, safe-area-context and keyboard-controller. It
  also neutralises `JSReanimated.setCSSEventHandler`, because Reanimated's own `/mock` entry
  throws on import under Jest since 4.6. Leave that in place.
- gesture-handler is set up separately, from `jestSetup.js` listed in `jest.config.cjs`
- gesture-handler 3's `GestureDetector` throws in development without a `GestureHandlerRootView`
  above it. `Chat` mounts one; a test that renders a lower-level component (a bubble, a player,
  `MessagesContainer`) imports `render` from `src/__tests__/renderWithGestureRoot.tsx` instead
- the safe-area and keyboard-controller mocks deliberately expose *real* contexts
  (`SafeAreaInsetsContext`, `KeyboardContext`) defaulting to the "no provider mounted" value,
  because `Chat` detects an app-level provider by reading them - a plain stub object would
  make that path untestable
- `resetMocks: true` is on, so set up spies inside each test.
- `testMatch` is `**/*.test.ts?(x)` and `example/` is excluded via `modulePathIgnorePatterns`,
  so the example app has no tests of its own

## Working in parallel worktrees

Agents can work in git worktrees under `.claude/worktrees/`. Link the dependencies instead of
installing (`ln -s <repo>/node_modules node_modules`, and the same for `example/node_modules`) and
remove the links before committing. Jest's default run also picks up those worktrees, so from the
main checkout run `yarn test --testPathIgnorePatterns '<rootDir>/.claude/'`.

## Running the example app

The example consumes the **built `lib/`**, not `src/`. After editing `src/`:

```bash
yarn build                # from the root - lib/ is what the app imports
cd example && yarn start  # already means `expo start --dev-client --clear`
```

Use the example's own `yarn start`, not the root one: the root script is a bare `expo start`
and misses the `--clear` a freshly built `lib/` needs. (`expo-dev-client` is not installed
here - the app is an ordinary prebuilt debug build that finds Metro on `localhost:8081`
either way, so `--dev-client` only changes what the CLI advertises; `--clear` is the flag
that matters.)

The `--clear` matters: Metro treats the linked `lib/` as a node_module and does not watch it,
so without a cache reset the app keeps serving the previous build. Files under `example/`
itself are in the project root and hot-reload normally, with no rebuild. `yarn build` also
deletes `lib/` before emitting it, so a Metro left running across a rebuild will fail with
`Failed to get the SHA-1 for: .../lib/...` - restart it rather than debugging that.

The demo screens send through `example/components/chat-examples/useDemoSend.ts`, which walks a
sent message through `pending`, `sent` and `received` the way a backend would; use it in new demos.
The demo screens are `example/app/chat/<id>.tsx` (routes, listed in `_layout.tsx` and the
Explore tab) wrapping `example/components/chat-examples/*Example.tsx` (the actual demos).
Jump straight to one with the app's URL scheme instead of tapping through the list:

```bash
xcrun simctl openurl booted 'example:///chat/media'   # bundle id com.anonymous.example
```

`example/ios` and `example/android` are generated and gitignored. If they go stale against
`example/node_modules`, regenerate rather than patching them:

```bash
cd example && yarn install && npx expo prebuild --clean
```

On Android the Metro port is baked into the debug build, so pass it at build time
(`npx expo run:android --port <n>`) rather than relying on `adb reverse`. When a Metro is
already running on that port, `--port` and `--no-bundler` refuse to combine; build with
`cd example/android && ./gradlew app:assembleDebug -PreactNativeDevServerPort=<n>` and
`adb install -r app/build/outputs/apk/debug/app-debug.apk` instead. The first launch after a
Metro restart can sit on a blank screen while the bundle builds; warm it with
`curl 'localhost:<n>/node_modules/expo-router/entry.bundle?platform=android&dev=true' -o /dev/null`.

On iOS, a debug build looks for Metro on 8081 unless the port is baked into `Info.plist` as
`RCTMetroPort`: `app.config.js` sets it from `RCT_METRO_PORT` at prebuild time
(`RCT_METRO_PORT=<n> npx expo prebuild --clean`, then rebuild the app). Without that, launch
with `-RCT_jsLocation localhost:<n>` to point one run at another port.

A release APK holds all four ABIs (~235 MB). For a device-only build pass
`-PreactNativeArchitectures=arm64-v8a` to `./gradlew app:assembleRelease`; it builds and
installs far faster.

The example runs react-native-worklets in **Bundle Mode** (for `react-native-streamdown`):
the Babel plugin has `bundleMode: true` and `metro.config.js` is wrapped in
`getBundleModeMetroConfig`. Changing either needs a Metro restart with `--clear` and a full app
relaunch, not a reload.

Android-only pitfalls seen in this library: a nested `<Text>` colored `'transparent'` inherits
its parent's color (use `HIDDEN_TEXT_COLOR` from `src/Bubble/styles.ts`), and a `TextInput`
focused in the frame it mounts gets the cursor but not the soft keyboard (use `autoFocus`).

## Dependency policy

The example is an **Expo SDK 58** app (React Native 0.88, React 19.3). `npx expo install --check`
is the first thing to run when a native build misbehaves, but it is **not** the final word
here: the example deliberately runs ahead of a few of Expo's pins, so the check reports those
as "should be updated" and would downgrade them. Read the table below before acting on it.
(`npx expo install --fix` also insists on installing the newest `expo` first, so within the
24-hour quarantine below it fails; align the `expo-*` packages by hand from `--check` then.)

Deliberately **ahead** of `expo install --check`:

| Package | Here | Expo SDK 58 wants | Why |
| --- | --- | --- | --- |
| `react-native-gesture-handler` | 3.4.x | ~3.3.0 | the library's own toolchain pins 3.4; downgrading splits the two |
| `react-native-worklets` | 0.13.1 | 0.13.0 | the patch release that ships with reanimated 4.7.1 |
| `react-native-keyboard-controller` | 1.22.x | 1.22.7 | the version the keyboard work in `src/` targets |
| `react-native-safe-area-context` | 5.11.x | ~5.10.1 | matches the library's toolchain |
| `@react-native-async-storage/async-storage` | 3.x | 2.2.0 | v3 is the current major; the example uses its default (legacy) storage, whose API is unchanged |
| `react` / `react-dom` | 19.3.1 | 19.3.0 | patch release; React Native 0.88 accepts `^19.3.0` |

Metro resolves package `exports` (`unstable_enablePackageExports` is left at its default): SDK 58
packages import each other through `exports` subpaths. Import deep paths the way a package's
`exports` map declares them - the Lucide icons come from `lucide-react-native/icons/<name>`, never
from its `dist/` files.

The chat stack uses `headerTransparent: false`. Expo Router 58's default transparent header makes
iOS 26 blur scroll content under it.

No native patches are carried any more. Worklets 0.12 renamed `WorkletRuntime::executeSync` to
`runSync`; `react-native-audio-api` 0.13.6 and `expo-modules-core` 58 call `runSync` upstream,
so the `.yarn/patches/` fixes and their `resolutions` wiring were removed. If a native package
fails to compile against the worklets headers after a bump, check its call sites first; add a
patch with `yarn patch` only if upstream has not caught up.

`react-native-vision-camera` 5 runs on Nitro (`react-native-nitro-modules` +
`react-native-nitro-image`, both direct dependencies of the example) and ships no Expo config
plugin, so its camera/microphone permission strings live in `app.json` (`ios.infoPlist`,
`android.permissions`).

Held back deliberately, with reasons - do not bump these casually:

| Package | Pinned at | Why |
| --- | --- | --- |
| `typescript` | 6.0.x | `@typescript-eslint` 8.72 declares `typescript >=4.8.4 <6.1.0`; TypeScript 7 breaks the lint |
| `@babel/*` | 7.x | `@react-native/babel-preset` 0.88 is built from Babel 7 plugins; under `@babel/core` 8 it throws `Requires Babel "^7.0.0-0"` |
| `remend` (example) | 1.3.0 | `react-native-streamdown` 0.3 pins its peer to exactly `1.3.0` |

Jest is on 30 even though `@react-native/jest-preset` 0.88 still lists `babel-jest` and
`jest-environment-node` 29 - the suite runs under Jest 30 as is. If a preset bump breaks that,
`jest.config.cjs`'s `transformIgnorePatterns` already keeps Jest's own packages out of Babel.

Yarn 4.17 applies a 24-hour publish age gate, so a just-released version can be refused as
"quarantined". That is expected - pick the previous version and move on.

## Releasing

Land the content first as normal commits, then cut the release as its own commit:

1. Move `CHANGELOG.md`'s `## [Unreleased]` heading to `## [X.Y.Z] - YYYY-MM-DD`. Entries are
   grouped under the emoji headings already in the file (`💥 Breaking`, `✨ Features`,
   `🐛 Fixes`, `⚡ Performance`, `🔧 Deprecations`, `📦 Dependencies`, `📝 Docs`,
   `📲 Example app`). Keep entries concise: one line each, what changed for the user and the
   prop or opt-out involved. Causes, measurements and investigation go in the commit message
2. Bump `version` in `package.json`. On a **major**, also bump the range in
   `expoSnack/package.json` - it is a caret on the library, so `^4.x` will not resolve `5.0.0`
   and the Snack would silently keep installing the old major. Point the README's two feature
   showcase GIFs (`media/features-light.gif`, `media/features-dark.gif`) at the new tag,
   `.../react-native-chat/vX.Y.Z/media/...`: GitHub and npm cache README images by URL, so a
   GIF re-recorded under the same `main` URL keeps showing the old one, and a tag URL also gives
   each npm version the GIF it shipped with
3. `yarn prepublishOnly` (lint + test + build) must pass
4. Commit as `chore: release X.Y.Z`, touching only those files (and the README's GIF URLs), with a body explaining the
   version choice and a `Verified:` line
5. Annotated tag: `git tag -a vX.Y.Z -m "X.Y.Z - short summary"` (the `v` prefix from 4.3.0 on;
   4.2.0 and earlier have none)
6. `git push origin main && git push origin vX.Y.Z`
7. Publish a GitHub Release on the tag, with that version's CHANGELOG section as the notes:
   `gh release create vX.Y.Z --title X.Y.Z --notes-file <section>`

Publishing the release is what ships to npm: `.github/workflows/release.yml` runs on
`release: published`, re-runs lint, typecheck, test and build, and runs
`npm publish --provenance` through npm trusted publishing (OIDC - there is no `NPM_TOKEN`).
Pushing the tag alone publishes nothing. Do not `npm publish` by hand; watch the run with
`gh run watch` and check `npm view @kesha-antonov/react-native-chat version` afterwards.

## Before you finish

```bash
yarn lint && yarn typecheck && yarn test && yarn build
```

All four must pass. Do not add AI attribution to commits, PR descriptions, or code comments.
